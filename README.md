# 小米运动健康 — Home Assistant 集成(国内适配版)

非官方 Home Assistant 集成,从小米**运动健康**(Mi Fitness / 小米运动健康)云同步
个人健康数据:步数、距离、卡路里、心率(当前/平均/静息)、睡眠(时长/深浅/REM/评分/
效率/体型/夜醒)、血氧、站立小时、**运动记录**(类型/距离/时长/卡路里 + 30 天历史)、体重。

> 基于上游 [batareya16/MiFitnessHass](https://github.com/batareya16/MiFitnessHass)(MIT)
> 深度国内适配:登录方式、数据接口、界面全面针对国内账号重做。

## 登录方式:浏览器链接登录(唯一方式)

配置时集成会给出一条**登录链接**,在电脑浏览器中点开 → 登录小米账号 → 确认,
集成后台自动完成对接。全程:

- **不需要输入密码**(密码登录在国内风控下基本走不通,已移除)
- **不需要手机扫码**(链接在电脑浏览器直接打开即可;二维码仅作手机端可选捷径)
- **不需要手动复制 token**
- 万一触发风控,验证在小米自己的登录页面里交互式完成,集成不做任何对抗
- 登录拿到 `passToken` 后,`serviceToken` 过期会**静默续期**,正常情况一次配置长期使用

数据读取为**账户级**:手环/手表/体脂秤同步到小米运动健康 App 的数据都会出现,
与具体设备无关。每 15 分钟轮询一次,历史数据在首轮同步后补齐。

## 安装

### HACS(推荐)

HACS → 自定义仓库 → 添加本仓库地址(类别:Integration)→ 安装「小米运动健康」
→ 重启 HA → 设置 → 设备与服务 → 添加集成 → 搜索「小米运动健康」。

### 手动

把 `custom_components/mi_fitness/` 整个目录复制到 HA 配置目录的
`custom_components/` 下,重启 HA。

## 配置

1. 添加集成,区域选 `cn`(国内账号)
2. 点开**登录链接**,在浏览器登录小米账号并确认
3. 完成。之后可在面板/自动化中使用 25 个实体(步数、心率、睡眠、运动记录等,名称已中文化)

## 传感器一览

步数/距离/卡路里(当日 + 14 天历史)、当前/平均/静息心率、睡眠时长/深睡/浅睡/REM/
评分/效率/夜醒次数/就寝/起床/体型、血氧、站立小时、今日活动时长、今日训练负荷
(含等级/近期累计属性)、**最新运动**(单实体:状态=运动类型,属性挂开始/结束时间/
时长/距离/配速字段/心率/卡路里/今日列表/30 天历史)、体重。

### 运动记录说明

运动记录来自 `POST /app/v1/data/get_sport_records_by_time`(签名 POST,端点出处
[mi-fitness-mcp-cn](https://github.com/HUAYUE1024/mi-fitness-mcp-cn) 云适配器,
CN 账号实测可用)。在手表/手环上**主动开始运动**(跑步、骑行等)才会生成记录;
普通走路只计入步数。记录按开始时间幂等入库(距离/卡路里等单调字段取大),
首次同步回填 30 天,之后每轮只拉最近 3 天窗口,30 天历史挂在「最新运动」实体的
`history_30d` 属性里。若日志出现「运动记录未识别的形状」,原始 JSON 已记录,
反馈即可完善解析。

## 技术说明

- 数据接口:`hlth.io.mi.com`(国内裸域),RC4+SHA1 签名,水位增量拉取
- 心率/睡眠等天级汇总来自 `daily_report` 聚合接口(国内账号的原始流不含这些条目)
- 运动记录:`POST /app/v1/data/get_sport_records_by_time` 签名 POST(新增
  `_build_post_form`/`_post`,GET 签名族的运动端点全 404,POST 才是正确形态),
  next_key 分页,按运动开始时间幂等入库
- 训练负荷来自原始流 `training_load` 项(当日项原地更新,判重用 update_time)
- 今日步数/距离取「原始流累计」与「日汇总聚合」的较大者:聚合接口有延迟,
  直接覆盖会把新鲜数据压回旧值(走 2km 后停在聚合延迟值就是这个坑)
- 低/中/高强度活力与建议活动实体已移除(更新极少、无实用价值);中高强度活动
  的可用读数是「今日活动时长」
- 凭证仅存于本机 HA 的 `.storage`,请勿将 HA 配置目录提交到公开仓库
